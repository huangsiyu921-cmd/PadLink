## §1 待决策（拍板后我按结论推进）

| # | 问题 | 选项 | 我的建议 |
|---|---|---|---|
| **D1** | ADB 到底指什么？ | (a) 手机↔PC 的 USB 传输通道；(b) 用手机虚拟手柄控制**手机自己**跑的游戏 | (a)。若是 (b)，虚拟手柄类型无意义，产品完全不同，需重写企划 |
| **D2** | 是否做蓝牙 HID 直连模式 | (a) 做，作为第三种传输模式；(b) 只做 WiFi/ADB | (a)，但排在 v0.4 之后（见 §3），先别摊薄精力 |
| **D3** | 起点策略 | (a) 参考实现 + 自研主干；(b) 整树 fork BuanaVPad 改造；(c) 从零 | (a) |
| **D4** | PC 端虚拟手柄后端 | (a) 先 ViGEmBus，抽象层留 VIIPER 切换；(b) 直接上 VIIPER | (a)：ViGEm 集成最快，先用它拿到"能玩"的状态 |
| **D5** | 移动端技术栈 | (a) Kotlin 原生 + Compose；(b) .NET MAUI 单语言 | 需要你选。选 (b) 前先做触摸延迟 spike（§2 的 P0.5） |
| **D6** | 震动反向通道走哪 | (a) UDP 反向包；(b) 复用控制 TCP；(c) 先不做 | (a)，但协议里**预留字段**，v0.1 先只定义不实现 |
| **D7** | 目标平台 | (a) 仅 Windows；(b) Windows + Linux | (a)。Linux 的 `uinput` 后端与 XInput 语义差异大，等 Windows 稳了再说 |

> 环境里的其它语言怎么用：**Go**——写协议压测器/发包器（模拟 4 个"假手机"狂发 UDP，验证 PC 端稳定性和 fail-safe）；**Python**——调研脚本、快速验证（Joy2DroidX 服务端就是 Python，可以直接跑起来对照握手行为）；**JS**——本方案不用（Electron 的延迟和体积在低延迟输入场景不划算）。

## §2 阶段计划

原则：**每个阶段结束都必须有一个"能用眼睛看到"的验收物**，不做纯理论阶段。

### P0 · 定契约（预计 2–3 天）

- [ ] D1–D7 拍板
- [ ] 克隆 `Joy2DroidX-server`（Python，映射逻辑最好读）、`buana-vpad`（UI 布局编辑器参考）、`VIIPER`（未来后端）到 `research/`，读源码而不是读 README
- [ ] 核实 `Joy2DroidX` 的 LICENSE 文件到底写的是什么
- [ ] 写出 `protocol/protocol.md` + 第一版测试向量（§02 §6 的草案直接落地）
- [ ] 产出 `src/pc/PadLink.sln` 骨架 + `src/android` 空工程骨架

**验收**：`protocol/protocol.md` 定稿，两端能各自编解码同一份测试向量并通过。

### P0.5 · 技术 spike（按 D5 决定是否做，1 天）

- [ ] 若选 MAUI：写一个真机 App，全屏自绘 2 个摇杆，测量触摸到屏幕更新的端到端延迟与帧率稳定性；不达标就退回 Kotlin
- [ ] 若选 Kotlin：同样测一遍，作为基线数字存档

**验收**：一个数字——"触摸到画面响应的 p95 毫秒数"，写进本文档。

### P1 · 垂直切片：一句话打通（预计 3–5 天）

不碰 UI，先证明链路成立：

- [ ] PC 端 C# 控制台程序：初始化 ViGEmBus → 创建一个 Xbox 360 虚拟手柄 → 监听 UDP
- [ ] 用 Python 写"假手机"（`tools/fake-pad.py`）：60Hz 发 §02 §6.2 的二进制帧，脚本参数控制各轴/按键
- [ ] 实现 fail-safe（300ms 超时归零）与 seq/丢包统计

**验收**：在 `joy.cpl`（或任意手柄测试网页）里，能用 Python 脚本让虚拟手柄的摇杆摆动、按键按下；`Ctrl+C` 杀掉脚本后 300ms 内所有输入自动归位。

### P2 · 真机 + WiFi 全链路（预计 1–2 周）

- [ ] 移动端：全屏自绘手柄 UI（左摇杆 / 右摇杆 / ABXY / 十字键 / 扳机），横屏锁定、沉浸全屏、常亮
- [ ] 摇杆数学模型：归一化、圆形裁剪、死区（可校准）、`lx/ly` 取整到 int16
- [ ] UDP 发现（广播）+ 手输 IP 兜底；Windows 防火墙提示
- [ ] 60Hz 固定节拍发送 + 无变化降频保活
- [ ] PC 端：会话管理、协议解析、映射到 XInput

**验收**：真机玩一款 3D 游戏（比如某个赛车/平台跳跃），能正常操作；拔掉 WiFi 后角色立即停止。

### P3 · ADB 模式（预计 3–5 天）

- [ ] PC 端检测 `adb` 可用性、自动执行 `adb reverse tcp:<port> tcp:<port>`（**注意方向是 reverse**）
- [ ] 移动端 TCP server 监听 `127.0.0.1:<port>` + `TCP_NODELAY`
- [ ] 支持无线调试（Android 11+）：`adb pair` 引导流程 + 状态提示
- [ ] 连接模式 UI（WiFi / ADB）

**验收**：打开 USB 调试插上线，手机自动被 PC 端接管，无需手动输 IP。

### P4 · DS4 后端 + 打磨（预计 1 周）

- [ ] 后端抽象 `IVirtualControllerBackend` 抽出，ViGEmBus 成为其中一个实现
- [ ] DS4 设备创建 + 映射表（按钮位掩码语义与 XInput 不同，单独一张表）
- [ ] 手柄类型切换 → 移动端布局模板随之切换（A/B/X/Y ↔ ✕/○/△/□）
- [ ] 布局编辑器（拖动/缩放按钮、多套配置保存）
- [ ] 配对码 + token 认证

**验收**：切到 DS4 模式后游戏里显示 PlayStation 按键提示；未配对设备无法创建虚拟手柄。

### P5 · 之后（按需）

- [ ] 震动反馈回传
- [ ] 多手柄（XInput 4 槽位 + 槽位管理 UI）
- [ ] VIIPER 作为第二后端（为 Linux 留路）
- [ ] 蓝牙 HID 直连模式
- [ ] 打包：PC 端单文件 exe + 驱动安装引导；Android 端签名 APK
